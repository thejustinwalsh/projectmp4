# projectmp4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust CLI that turns a finished audio track into a shareable 1080p60 music-visualizer mp4, with projectM visuals chosen by community curation, preset switches landing on neural-detected downbeats, and a GH0STF1R3 watermark.

**Architecture:** One binary. libprojectM 4.2 (pinned master) is driven offline through a headless CGL context rendering into an FBO, with its clock fed by us rather than the wall clock, so rendering runs as fast as the GPU allows. Beat and downbeat analysis comes from agent-deck's existing Rust crates. Raw frames are composited with an overlay and piped to ffmpeg.

**Tech Stack:** Rust 2021 (rustup), libprojectM 4.2 via FFI, `deck-track-analysis` + `deck-media-codec` (path deps), `tiny-skia` + `resvg` + `cosmic-text` overlay, `winit`/`glutin`/`cpal` preview, ffmpeg 7.1.1 subprocess.

**Spec:** `docs/superpowers/specs/2026-11-03-projectmp4-design.md`

## Global Constraints

- Target **macOS 27.2 / Apple Silicon only**. No cross-platform code paths.
- Binary name is **`projectmp4`**. Crate name `projectmp4`. No `gf3` alias anywhere.
- libprojectM pinned to **commit `eae22de4`** as a git submodule at `vendor/projectm`. CMake `VERSION 4.2.0`. Never link Homebrew's `projectm` (3.1.12 — lacks the v4 C API).
- **48 kHz is the pipeline rate throughout.** Decode, analysis, stems, and PCM fed to projectM. The only resample is ffmpeg's at the normalise step.
- Every input is normalised to a temp **48 kHz WAV via ffmpeg** before analysis or rendering. `deck-media-codec` does not enable symphonia's mp3 feature; **never edit agent-deck to fix this.**
- **agent-deck is read-only.** Never write into `~/Library/Application Support/agent-deck/`.
- Output: **1920x1080**, 60fps default, `libx264 -crf 17 -preset slow -pix_fmt yuv420p -movflags +faststart`, audio AAC 256k. Muxed audio is always the **full mix**.
- Watermark is **cold white, single colour, no accent**.
- Preset packs are **never committed** — only `presets/sources.toml` (pinned commits) and the generated `presets/profiles.toml`.
- **N = 40** presets per profile. Tier bonuses: **+30%** BLTC, **+20%** Winamp stock, **+20%** Geiss favorites.
- Switch cadence: **minimum 8 s** between switches; a detected drop may override down to **4 s**. Hard cut on a drop, **2 s** soft blend otherwise.
- `dubstep` is an alias of the `deathstep` profile.
- Rust toolchain via rustup is a documented **prerequisite**, not installed by `build.rs`.

## Review Focus

Input classes the spec implies but no task's happy path exercises. Each has a test pinned to the task that owns the code.

1. **An mp3 input** — the whole Suno workflow. `deck-media-codec` cannot decode mp3; if normalisation is skipped or mis-ordered the primary use case fails. (Task 3)
2. **A track with no agent-deck cache and no stems** — a fresh download. Must analyse from scratch and drive from the full mix, not error. (Tasks 4, 5)
3. **A preset that fails shader compilation or renders all black mid-render** — documented to exist in libprojectM. Must skip to the next preset, never abort a render that is minutes in. (Task 12)
4. **Missing, non-square, or unreadable cover art** — layout must not shift or panic; render proceeds without the art block. (Task 10)
5. **A track shorter than the 8 s minimum switch interval** — the 12 s and 17 s fixtures hit this. Must produce one preset for the whole track, not divide by zero or emit a switch past the end. (Task 6)

- [ ] **Step 3: Implement `plan_switches`**
